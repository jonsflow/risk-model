Trading Session File

Each generator run computes one stage and appends it to the day's data/cache/trading_signals_<date>.json. A stage is written once. Later stages read what earlier ones wrote but never recalculate it, so the morning call stays what we were advised, and the recap can judge it.

Who scores what

SessionFile

MemberDoes
open(cache_dir, session_date, stages)Loads the day's file if it exists. Any stage missing from it starts as not available.
has(name)True once the stage is written, meaning its section isn't the not-available one.
sections()A deep copy of every section, for the builder to read.
append(name, section)Adds the stage's section. Raises if it's already written.
save(generated)Writes session_date, generated (time of the last write), market_closed and the four sections in order.

Entry points

CallerHow it runs the generator
pipeline.run generateThe workflow's step. Takes the latest stage whose data is there.
pipeline.run trading --stage NAMEJust that stage, for the date's session (--date, default latest).
scripts/backfill_trading_history.pyEvery stage, in order, per trading day. Without --force it fills in missing stages; --force deletes the day's file first.
tests/test_trading_stages.pyReplays the latest stored session into one file at 09:00, 09:40, 13:00 and 17:00. Checks which sections exist, that earlier sections are unchanged byte-for-byte, and that each equals a fresh backfill. Also checks that the previous session backfills every stage and that a stage is written once.

Rules

  • A stage is calculated once. Only a backfill goes backwards.
  • A stage reads its own time series (bars ended by its window end) plus earlier sections; it never recomputes them.
  • Opening range and recap need premarket written; otherwise the run does nothing.
  • Each stage scores only its own calls; the recap grades them from the file.
  • Intraday bar files under data/cache/intraday/ are still written on every run. They aren't part of the append-only record.
